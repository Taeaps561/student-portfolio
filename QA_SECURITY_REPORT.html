✅ ใช้กลไกตรวจสอบหลายชั้น (Multi-Layer Verification)

1. Teacher Verification อาจารย์อนุมัติ ทักษะที่นักศึกษาเพิ่มเองมีสถานะ PENDING_TEACHER_REVIEW จนกว่าอาจารย์จะ Approve

5. Audit Trail บันทึกทุกการกระทำ ทุกการเพิ่ม/แก้ไข/อนุมัติถูก log ใน AuditLog พร้อม userId, IP, timestamp

✅ ระบบใช้ 7-Layer File Security ตาม OWASP

ความเสี่ยงหลักจาก File Upload:

ความเสี่ยงอธิบายตัวอย่าง
Malware/Virusไฟล์อันตรายแฝงมาshell.exe เปลี่ยนนามสกุลเป็น .pdf
Path Traversalชื่อไฟล์มี ../../../etc/passwd.pdf

วิธีป้องกันที่ระบบทำ (7-Layer Security):

1
MIME Type Whitelist
เฉพาะ PDF, JPG, PNG เท่านั้น
2
Magic Bytes Check
ตรวจ Binary Signature จริง (ป้องกัน MIME Spoofing)
3
File Size Limit
จำกัด ≤ 5MB (ป้องกัน DoS)
4
Filename Sanitization
ตัด ../ null bytes อักขระอันตราย
5
File Rename
ไม่ใช้ชื่อจากผู้ใช้ — ตั้งชื่อใหม่ด้วย UUID
6
SHA-256 Hash
hash ไฟล์เพื่อ integrity และป้องกัน duplicate
7
Audit Log
บันทึก IP, hash, ชื่อไฟล์ ทุกครั้งที่อัปโหลด
5
หากนายจ้างได้รับ Link สำหรับตรวจสอบ Portfolio ระบบจะทำให้มั่นใจได้อย่างไรว่าข้อมูลไม่ถูกแก้ไขหรือปลอมแปลง
✅ ใช้ Digital Certificate Verification ด้วย SHA-256
[นักศึกษาอัปโหลดใบรับรอง] ↓ [ระบบ Hash ไฟล์ด้วย SHA-256] hash = SHA256(file_bytes) → "a3f5c2d1..." ↓ [เก็บ hash ไว้ใน Database (hashValue — UNIQUE)] ↓ [สร้าง Verification URL] https://skillpassport.sdu.ac.th/verify?h=a3f5c2d1... ↓ [นายจ้างเปิด Link → ระบบดึง Certificate จาก DB ตาม hash] ↓ ✅ Certificate ถูกต้อง หรือ ❌ ไม่พบหรือถูกแก้ไข

ทำไม Hash จึงปลอมไม่ได้:

  • SHA-256 เป็น One-way function — เปลี่ยนแม้ 1 ตัวอักษร hash จะเปลี่ยนทั้งหมด
  • hashValue ถูก mark เป็น @unique ใน Database — ใส่ซ้ำไม่ได้
  • Verification Link ไม่มีข้อมูล Certificate ใน URL — ดึงจาก DB ตาม hash เท่านั้น

// Whitelist MIME types ที่อนุญาต
const ALLOWED_MIME_TYPES = new Set([
  "application/pdf", "image/jpeg", "image/png"
]);

// Whitelist นามสกุลที่อนุญาต
const ALLOWED_EXTENSIONS = new Set([
  ".pdf", ".jpg", ".jpeg", ".png"
]);

ฟังก์ชัน sanitizeFilename() — ป้องกัน Path Traversal

function sanitizeFilename(originalName: string): string {
  // 1. ดึงแค่ basename → ตัด ../../ ออกทันที
  const basename = path.basename(originalName);

  // 2. ลบ null bytes และอักขระอันตราย
  const safe = basename
    .replace(/\0/g, "")                           // null bytes
    .replace(/[^a-zA-Z0-9.\-_\u0E00-\u0E7F]/g, "_") // อักขระพิเศษ
    .substring(0, 100);                            // จำกัดความยาว

  // 3. ตรวจนามสกุลไฟล์
  const ext = path.extname(safe).toLowerCase();
  if (!ALLOWED_EXTENSIONS.has(ext)) {
    throw new Error(`ประเภทไฟล์ไม่ได้รับอนุญาต: ${ext}`);
  }
  return safe;
}

ขั้นตอนทั้งหมดใน POST Handler (13 ขั้นตอน)

Step 1: ตรวจ Session → 401 ถ้าไม่ได้ login Step 2: Parse FormData → รับ file, name, issuer, issueDate Step 3: Required check → 400 ถ้าข้อมูลไม่ครบ Step 4: File size check → 413 ถ้าเกิน 5MB Step 5: MIME type check → 415 ถ้าไม่ใช่ PDF/JPG/PNG Step 6: Sanitize filename → ป้องกัน Path Traversal Step 7: Magic bytes verify → ตรวจ binary signature จริง Step 8: Compute SHA-256 → hash ไฟล์เพื่อ integrity Step 9: Ownership check → หา Portfolio ของ user นั้น Step 10: Duplicate check → ป้องกัน hash ซ้ำ (409) Step 11: Save to Database → บันทึก cert + hash Step 12: Audit Log → บันทึก IP, hash, filename Step 13: Return response → ไม่ส่ง fileUrl กลับโดยตรง
