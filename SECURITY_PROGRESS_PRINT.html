1. การประเมินความเสี่ยงของเว็บแอปพลิเคชัน (Risk Assessment)

ระบบพัฒนาด้วย Next.js 16 (App Router), React 19, Prisma ORM, NextAuth.js มีการระบุทรัพย์สินสำคัญ (Assets), จุดที่ผู้โจมตีเข้าถึงได้ (Attack Surface) และจัดทำทะเบียนความเสี่ยง (Risk Register) ดังนี้:

1.1 การระบุ Asset สำคัญ และ Attack Surface

รหัส Asset ทรัพย์สินสำคัญ (Key Asset) Attack Surface (จุดเชื่อมต่อที่เข้าถึงได้) ภัยคุกคามเป้าหมาย (Threats)
A-01: User Data ข้อมูลนักศึกษา (ชื่อ, อีเมล, เบอร์โทร, เกรด GPA) `GET /api/portfolio`, `POST /api/employer/matching` Broken Access Control, ข้อมูลส่วนบุคคลรั่วไหล (PDPA)
A-02: Certificate ใบประกาศนียบัตรดิจิทัล & Verified Skills `GET /api/certificates/verify?hash=...` การปลอมแปลงใบรับรอง (ป้องกันด้วย SHA-256 Signature)
A-03: Session/Auth Session Cookie (`next-auth`), JWT, OAuth Token หน้าเข้าสู่ระบบ `/login`, `POST /api/auth/...` Credential Stuffing, Bypass รหัสผ่าน, Brute-Force
A-04: Database ฐานข้อมูล SQLite / PostgreSQL (10 Models) ฟอร์มกรอกข้อมูล, ช่องค้นหา, พารามิเตอร์ Filter SQL Injection (ป้องกันด้วย Parameterized Queries 100%)
A-05: Web Server HTTP Response Headers ของ Next.js ทุก Web Route และ API Endpoints (`/:path*`) Clickjacking (UI Redressing), MIME Sniffing, SSL Strip

2. การวิเคราะห์จุดอ่อนและช่องโหว่ของระบบ (Vulnerability Analysis)

วิเคราะห์ตามเงื่อนไข: "ช่องโหว่คืออะไร ➔ เกิดที่ส่วนใด ➔ มีผลกระทบอย่างไร" จากการตรวจสอบระบบจริง:

ช่องโหว่คืออะไร (Vulnerability) เกิดที่ส่วนใด (Location in Code) มีผลกระทบอย่างไร (Impact Analysis) มาตรฐานความปลอดภัย
1. Missing HTTP Security Headers
(ขาดการตั้งค่าส่วนหัวความปลอดภัย)		 `next.config.ts` (ขาดฟังก์ชัน `headers()`) ส่งผลต่อทุก Route ในเว็บ ผู้ไม่หวังดีสามารถนำเว็บไปทำ Clickjacking ฝังใน `<iframe>` หลอกกดปุ่มสำคัญ หรือทำ MIME Sniffing OWASP A05:2021 (Security Misconfiguration) / CWE-1021, CWE-16
2. Broken Access Control & PDPA Leak
(การเข้าถึงข้อมูลโดยไม่ตรวจสอบสิทธิ์)		 `src/app/api/portfolio/route.ts` และ `src/app/api/employer/matching` บุคคลภายนอกที่ไม่ล็อกอินสามารถดูเกรดเฉลี่ย (GPA), เบอร์โทรศัพท์ และโปรไฟล์ส่วนตัวของนักศึกษาทั้งสถาบันได้ OWASP A01:2021 (Broken Access Control) / ผิด พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล (PDPA)
3. Broken Authentication Flow
(ตรรกะตรวจสอบยืนยันตัวตนบกพร่อง)		 `src/app/api/auth/[...nextauth]/route.ts` (ในฟังก์ชัน `authorize`) หากทราบอีเมล สามารถป้อนรหัสผ่านอะไรก็ได้เพื่อข้ามการตรวจสอบเข้าสู่ระบบ เนื่องจากโค้ดขาดการ Validate OWASP A07:2021 (Identification & Auth Failures) / CWE-287
4. Outdated Vulnerable Dependencies
(แพ็กเกจภายนอกมีช่องโหว่ความปลอดภัย)		 `node_modules/next-auth` (<=4.24.14) และ `next` (v16.2.9) ช่องโหว่ Critical Unicode homoglyph bypass ใน next-auth และ Server Action SSRF ใน next.js OWASP A06:2021 (Vulnerable and Outdated Components)

4. การแก้ไขช่องโหว่และการแสดง Before / After (Security Remediation)

ตอบสูตร: "พบอะไร ➔ เสี่ยงอย่างไร ➔ แก้อย่างไร ➔ ตรวจสอบหลังแก้แล้วเป็นอย่างไร" พร้อมหลักฐาน Source Code จริง 2 จุด:

📌 จุดที่ 1: การเพิ่ม HTTP Security Headers ใน `next.config.ts` (แก้ OWASP ZAP Alerts)

• พบอะไร / เสี่ยงอย่างไร: ZAP ฟ้อง Missing Headers เสี่ยงต่อ Clickjacking (นำเว็บไปซ้อนเฟรมหลอกคลิก) และ MIME Sniffing
• แก้อย่างไร / ผลหลังแก้: ฉีด Security Headers 7 ตัวใน `next.config.ts` ➔ ทดสอบด้วย cURL และ ZAP Alerts ลดเหลือ 0 รายการ

❌ ก่อนแก้ไข (BEFORE) — ไม่มี Security Headers:
const nextConfig: NextConfig = { /* ว่างเปล่า ไม่มีการกำหนด Headers */ };
✅ หลังแก้ไข (AFTER) — ฉีด 7 Security Headers ครอบคลุมทุก Route:
const securityHeaders = [ { key: "Strict-Transport-Security", value: "max-age=63072000; includeSubDomains; preload" }, { key: "X-Frame-Options", value: "SAMEORIGIN" }, // ป้องกัน Clickjacking 100% { key: "X-Content-Type-Options", value: "nosniff" }, // ป้องกัน MIME-type Sniffing { key: "Referrer-Policy", value: "strict-origin-when-cross-origin" }, { key: "Permissions-Policy", value: "camera=(), microphone=(), geolocation=()" }, { key: "Content-Security-Policy", value: "default-src 'self'; script-src 'self' 'unsafe-eval' 'unsafe-inline'; frame-ancestors 'self';" }, ]; const nextConfig: NextConfig = { async headers() { return [{ source: "/:path*", headers: securityHeaders }]; }, };

📌 จุดที่ 2: การแก้ไข Broken Access Control และทำ PDPA Data Masking (`api/portfolio`)

• พบอะไร / เสี่ยงอย่างไร: Burp Suite ตรวจพบ API ส่งเกรด GPA, เบอร์โทร และโปรไฟล์ Private ให้บุคคลภายนอก ผิดกฎหมาย PDPA
• แก้อย่างไร / ผลหลังแก้: เขียนโค้ดกรอง `isPublic` และทำ Data Masking เบอร์โทรเป็น `081-XXX-XXXX` ซ่อน GPA สำหรับคนนอก

❌ ก่อนแก้ไข (BEFORE) — ส่งโปรไฟล์ Private และข้อมูลอ่อนไหวออกมาโดยตรง:
// HTTP Response: {"isPublic": false, "phoneNumber": "0812345678", "gpa": 3.85}
✅ หลังแก้ไข (AFTER) — บังคับกรอง isPublic: true และทำ Data Masking สำหรับผู้ใช้ทั่วไป:
const isPrivileged = session?.user?.role === "TEACHER" || session?.user?.role === "EMPLOYER"; const whereClause = (!session || !isPrivileged) ? { isPublic: true } : {}; const sanitizedPortfolios = portfolios.map((p) => ({ ...p, phoneNumber: isPrivileged ? p.phoneNumber : p.phoneNumber?.replace(/^(\d{3})\d{3}(\d{4})$/, "$1-XXX-$2"), gpa: isPrivileged ? p.gpa : null, // ซ่อนเกรดเฉลี่ยจากบุคคลภายนอกตามหลัก PDPA })); // HTTP Response: {"isPublic": true, "phoneNumber": "081-XXX-5678", "gpa": null}
